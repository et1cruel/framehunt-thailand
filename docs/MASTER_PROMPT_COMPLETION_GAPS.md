# FRAMEHUNT THAILAND — Master Prompt ปิดช่องว่างภาพและภาษา

ใช้ prompt นี้ต่อจาก `MASTER_PROMPT.md` เมื่อรับงานปิดรายการที่ยังขาดภาพ
ตรวจสอบ URL/สิทธิ์ภาพ หรือทำภาษาอังกฤษให้ครอบคลุมทั้งเว็บไซต์ ให้ทำงานกับ
repository และข้อมูลจริงของ Framehunt Thailand เท่านั้น แล้วลงมือแก้ให้เสร็จ
เป็นชุดที่ build, preview และ deploy ได้ ห้ามตอบด้วยแผนงานอย่างเดียว

## เป้าหมายรอบนี้

ปิดช่องว่างภาพที่ audit พบในมือสอง ร้านอาหาร กิจกรรม ห้องซ้อม โปสเตอร์งาน
ถ้ำ และพื้นที่ศิลปะ พร้อมตรวจภาพที่มีอยู่แล้วให้แยกสถานะจริง และทำให้ทุกหน้า
ที่ผู้ใช้เห็นรองรับไทย/อังกฤษโดยไม่มีข้อความ UI ภาษาไทยหลุดในโหมดอังกฤษ
ตัวเลขตั้งต้นต้องอ่านจาก `npm run audit:directory-covers` ทุกครั้ง ห้ามยึด
จำนวนจาก prompt หรือรายงานเก่า

## กติกาภาพและสิทธิ์

ภาพที่จะใช้เป็นภาพจริงของสถานที่หรือโปสเตอร์งานนั้น และมีหลักฐานยืนยันสิทธิ์
สำหรับการแสดงบนเว็บไซต์ ต้องเก็บข้อมูลต่อไปนี้เป็นรายภาพ:

- `url`, `source`, ชื่อไฟล์/ชื่อภาพ และ `identityEvidence` ที่ชี้ว่าภาพตรงกับ
  สถานที่นั้น (เช่น หมวด Commons ของสถานที่, entity ที่ตรงกัน, ข้อความจาก
  เจ้าของสถานที่ หรือหลักฐานผู้ใช้ส่งภาพ)
- `credit`, ชื่อผู้ถ่าย/ผู้สร้าง และชื่อใบอนุญาตแบบเต็มพร้อม `licenseUrl`
- `checkedAt`, สถานะการตรวจ URL, สถานะยืนยันตัวสถานที่ และสถานะสิทธิ์
- สำหรับรูปหลายรูป เก็บลำดับภาพปกและเหตุผลที่เลือก signature view

แหล่งที่รับได้:

1. Wikimedia Commons เมื่ออ่าน file description/API ของไฟล์นั้นโดยตรงแล้ว
   ยืนยัน author, license และ source; อนุญาตเฉพาะ Public Domain, CC0,
   CC BY หรือ CC BY-SA ที่ใช้เชิงพาณิชย์ได้และใส่ attribution ได้ครบ
2. เว็บไซต์ทางการ/ผู้จัด เมื่อเงื่อนไขการใช้ภาพหรือหนังสืออนุญาตยืนยันสิทธิ์
   การนำภาพมาแสดงใน Framehunt ได้ชัดเจนและมีหลักฐานที่บันทึกไว้
3. ภาพที่ผู้ใช้หรือทีมงานเป็นเจ้าของ พร้อมบันทึกผู้ส่งและขอบเขตการอนุญาต

ไม่ใช้ภาพจาก Google Maps, Facebook, Instagram, แหล่งข่าว, เว็บรวมร้าน หรือ
ผลค้นหารูป เพียงเพราะเปิดดูหรือ hotlink ได้; ไม่ใช้ CC BY-NC, CC BY-ND,
ภาพ AI, stock ทั่วไป, ภาพของสถานที่ใกล้เคียง หรือภาพที่จับคู่จากชื่อคล้ายกัน
โดยไม่มีหลักฐานยืนยัน ห้ามอนุมานสิทธิ์จากการมี URL หรือเครดิตชื่อเว็บ

ระบบค้นหาภาพต้องทำงานแบบ candidate ก่อน publish: บันทึกผู้สมัครและหลักฐาน
แยกจากภาพที่เผยแพร่จริง; อัตโนมัติได้เฉพาะการอ่าน metadata, license, file
type, response และ duplicate hash. การจับคู่อัตลักษณ์ภาพต้องมีหลักฐานตรงกับ
สถานที่และผ่านการทบทวนก่อนเปลี่ยนเป็น `verified` ห้ามนำ candidate ที่ยัง
คลุมเครือไปใช้เป็นภาพปก

โปสเตอร์งานต้องมาจากผู้จัด/ศิลปินที่อนุญาตหรือจากไฟล์ที่มี license ชัดเจน
พร้อมบันทึกวันงานและวันที่ตรวจประกาศ หากหาโปสเตอร์ที่ใช้ได้ไม่ได้ ให้แสดง
สถานะไม่มีโปสเตอร์กับลิงก์ประกาศทางการ และคงรายการนั้นไว้ใน audit

## ขั้นตอนปฏิบัติ

1. อ่าน `AGENTS.md`, ตรวจ branch, diff และไฟล์ที่ยังไม่ commit; ห้ามรวมไฟล์
   ที่ไม่เกี่ยวกับงานเข้ากับ commit
2. รัน audit ล่าสุดและสร้างรายการระเบียนที่ขาด โดยหักรายการซ้ำจากชื่อ จังหวัด
   พิกัด และ source identifier ก่อนนับ ห้ามนับ URL อย่างเดียวว่าเป็นภาพครบ
3. ตรวจ metadata, source และ license ของภาพที่มีอยู่ทุกหมวด แยกผลเป็น
   `verified`, `unreachable`, `blocked/unknown`, `wrong-content`,
   `license-unknown`, `missing` และ `pending-review`; สถานะ blocked/unknown
   ห้ามรายงานเป็น broken โดยไม่มีหลักฐาน
4. เติมภาพจากแหล่งที่ผ่านเกณฑ์ทีละชุด โดยเริ่มจากจำนวนขาดมากและหมวดที่ผู้ใช้
   ใช้เพื่อวางแผนจริง; ยืนยันตัวตนและสิทธิ์ของแต่ละภาพก่อน publish
5. ทำ audit ให้ตรวจทุก URL เมื่อสั่ง full check พร้อม retry, timeout ที่จำกัด,
   concurrency ที่สุภาพ, progress และ checkpoint; เพิ่ม `--limit` สำหรับ sample
   และแยกผลของ local asset กับ remote URL
6. สแกน React routes/components และข้อความที่ render จากข้อมูล เพื่อหาข้อความ UI
   ที่ยังไม่มี English key ใน `src/i18n/en.json`; เติมคำแปลที่ทบทวนแล้วทุก
   heading, paragraph, control, filter, badge, empty/loading/error/success,
   dialog, tooltip, alt text, footer และ screen-reader label
7. คงชื่อเฉพาะ/ชื่อร้านเป็นชื่อเดิมได้ แต่ห้ามปล่อยข้อความอธิบายหรือป้าย UI
   ภาษาไทยโดยไม่จำเป็นในโหมด English; ถ้า data ไม่มี English translation ให้
   เติมฟิลด์ `*_en` ที่ถูกต้องหรือใช้คำแปลที่มีหลักฐาน ห้ามเดาชื่อทางการ
8. ตรวจไทยและอังกฤษบนทุก route หลัก, ค้นหา/กรอง, back/forward, load more,
   keyboard focus, จอมือถือ, reduced-motion และภาพที่โหลดผิดพลาด โดยไม่ตัด
   ความสามารถเดิม
9. รัน `npm run audit:directory-covers`, `npm run build`, และ
   `npm run verify:preview`; ตรวจ production assets หลัง deploy เมื่อมี
   authorization ที่ยังใช้ได้
10. อัปเดต README และ `docs/VERIFICATION.md` ด้วยวันที่, จำนวนจริง, วิธีตรวจ,
    URL ที่ตรวจได้, commit/deployment และข้อจำกัด ห้ามใช้คำว่า “ครบ” หากยังมี
    missing, pending, blocked/unknown หรือ license-unknown

## เกณฑ์ปิดงาน

- รายการที่เผยแพร่ทุกใบมีภาพสถานที่/โปสเตอร์ที่ตรงตัวตน พร้อม source, credit,
  license และหลักฐานใช้สิทธิ์; ไม่มี fallback ภาพทั่วไปมาปิดช่องว่าง
- audit แสดง `missing=0`, `pending-review=0` และ `license-unknown=0` สำหรับ
  ขอบเขตที่ประกาศว่าปิดแล้ว; URL ที่ถูกบล็อกต้องเปิดเผยเป็นข้อจำกัด ไม่แอบนับ
  ว่าผ่าน
- English mode ไม่มีข้อความ UI ภาษาไทยที่หลุดจากการแปล; ชื่อเฉพาะภาษาไทย
  ต้องคงไว้ได้เมื่อเป็นชื่อทางการ และข้อความข้อมูลต้องอ่านรู้เรื่อง
- build, preview routes และ production assets ผ่าน; รายงานผลแยก local,
  committed, pushed, deployed และ production-verified

ถ้าบางรายการไม่มีภาพที่อนุญาตให้ใช้ อย่าฝืนใช้ภาพผิดหรือไม่มีสิทธิ์ ให้คง
สถานะค้างพร้อมเหตุผลและแหล่งที่ค้นแล้วอย่างตรวจสอบได้ และอย่าประกาศว่างาน
ครบจนกว่าจะปิดสถานะนั้นจริง
