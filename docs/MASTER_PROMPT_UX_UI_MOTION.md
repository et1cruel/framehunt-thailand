# FRAMEHUNT THAILAND — UX/UI & Motion Master Prompt

ใช้ prompt นี้พัฒนา UX, UI และ animation ของเว็บไซต์ Framehunt Thailand ใน
repository เดิม ทำงานต่อจากของจริงในโค้ด ห้ามสร้างเว็บตัวอย่างหรือเปลี่ยน
ผลิตภัณฑ์เป็นแนวคิดใหม่

## เป้าหมายของผู้ใช้

ช่วยให้คนหาและตัดสินใจเลือกสถานที่ได้เร็วขึ้น ตั้งแต่ค้นหาจากชื่อ จังหวัด
หมวดหมู่ หรือบรรยากาศ เปิดดูภาพจริงและข้อมูลก่อนเดินทาง แล้วบันทึกสถานที่ลง
บอร์ดเพื่อวางแผนต่อได้โดยไม่หลงทาง

ให้ความสำคัญกับงานหลักสามอย่าง:

1. **ค้นพบ:** พิมพ์ค้นหา ใช้ตัวกรอง และเปรียบเทียบสถานที่จากภาพกับจังหวัด
2. **ตรวจสอบ:** เปิดหน้าสถานที่ ดูภาพหลายมุม เครดิต แผนที่ และข้อมูลการเข้าถึง
3. **วางแผน:** บันทึกรายการโปรด จัดสถานที่ลงบอร์ด และกลับมาทำต่อได้

## ขอบเขตและความจริงของผลิตภัณฑ์

- รักษา React, TypeScript, React Router, Tailwind และ Framer Motion ที่มีอยู่
  อย่าเพิ่ม dependency เพื่อทำ transition ที่ CSS ทำได้อยู่แล้ว
- รักษาเส้นทาง ฟังก์ชันค้นหา ตัวกรอง URL, สองภาษา, สถานะภาพและข้อมูลจริง
  ห้ามตัดเมนูหรือเนื้อหาเดิมเพื่อทำให้หน้าดูโล่ง
- สถานที่หลักกับไดเรกทอรีกิจกรรม ร้านอาหาร ร้านมือสอง ห้องซ้อม และเวทีดนตรี
  มีระดับการตรวจสอบต่างกัน ต้องแสดงสถานะตามข้อมูลจริง
- เครดิต ใบอนุญาต แหล่งภาพ และคำเตือนการอนุญาตถ่ายทำต้องอยู่ครบ
- ก่อนแก้ ให้เปิดหน้าจอจริงและ trace component ที่เป็นเจ้าของพฤติกรรมนั้น
  ห้ามเพิ่ม global rule ที่ไปเปลี่ยนหน้าอื่นโดยไม่ตรวจผล

## ทิศทางภาพที่ล็อกไว้

ยึด visual system แบบ **soft glassmorphism + clay** ที่ผู้ใช้เลือกไว้:

- พื้น frost `#F8FAFF`, soft blue `#EDF1F9`, ตัวอักษร slate `#243143` และ
  concrete `#526175`
- ปุ่มหลัก evergreen `#315C53`; ใช้ sage, lilac และ peach เป็นสีรองอย่างพอดี
- ใช้ภาพสถานที่จริงเป็นองค์ประกอบหลัก ตัวหนังสือต้องอ่านง่ายและคอนทราสต์ชัด
- รักษา Plus Jakarta Sans และ IBM Plex Sans Thai รวมถึงส่วนโค้งและเงา clay
- ใช้ glass เฉพาะจุดที่ต้องแยกชั้นหรือวางข้อมูลทับภาพ ไม่เพิ่ม blur ทุกพื้นผิว
- รักษา copy ที่สั้น ชัด และบอกผลของการกดปุ่มโดยตรง

## หลัก UX ที่ต้องได้

- แถบนำทาง desktop มีลำดับหลักที่มองเห็นทันที และย้ายหน้ารองเข้าเมนูเพิ่มเติม
  เมื่อมีลิงก์มากเกินพื้นที่ แต่ทุกหน้าเดิมต้องเข้าถึงได้ทั้ง desktop และมือถือ
- ห้ามชื่อแบรนด์ เมนู ปุ่มภาษา ค้นหา หรือรายการโปรดเบียดหรือซ้อนกันเมื่อย่อจอ
- คง search suggestion ที่ใช้ลูกศร, Enter และ Escape ได้ ให้ focus และรายการที่
  เลือกอยู่มองเห็นชัด
- ตัวกรองต้องบอกค่าที่เลือก ล้างค่าได้ และยังสะท้อนใน URL; empty, loading และ
  error state ต้องบอกทางไปต่อ
- ปุ่มสำคัญและจุดกดบนมือถือมีพื้นที่แตะอย่างน้อย 44×44 px พร้อม focus ring
- อย่าใช้สีเพียงอย่างเดียวบอกสถานะ และอย่าทำให้ภาพที่กำลังเปลี่ยนไปรบกวนการอ่าน
- ทุกหน้าใช้ได้ด้วย keyboard และภาษาไทย/อังกฤษ โดยไม่เปลี่ยนความหมายของ control

## Motion thesis: เปลี่ยนโฟกัสไปยังภาพของสถานที่

Framehunt เป็นเครื่องมือเลือกเฟรมและสถานที่ ให้ motion ทำหน้าที่คล้ายการปรับ
โฟกัสของกล้อง: หน้านิ่งและอ่านได้ก่อน ผู้ใช้จึงสั่งให้ภาพเคลื่อน

- **ช่วงสำคัญหนึ่งเดียว:** เมื่อชี้หรือ keyboard-focus การ์ดสถานที่ ให้ภาพของ
  สถานที่นั้นค่อย ๆ crossfade เป็นภาพยืนยันมุมอื่นทุกประมาณ 3.5 วินาที พร้อม
  ตัวนับภาพและเครดิตที่อ่านได้ การเปลี่ยนต้องไม่ดูเหมือนเป็นภาพของสถานที่อื่น
- หยุดทันทีเมื่อ pointer ออก, focus ออก, การ์ดอยู่นอกจอ, แท็บไม่ active หรือ
  `prefers-reduced-motion: reduce` เปิดอยู่
- การเปิดเมนู, suggestion และการกดปุ่มใช้ feedback สั้น 120–220 ms; overlay
  หรือ gallery ใช้ได้ถึง 300 ms เมื่อช่วยบอกการเปลี่ยน state
- เร็วตอนออกกว่าตอนเข้า ใช้ easing ที่นุ่มและชัด ไม่มี bounce โดยปริยาย
- ไม่ใส่ scroll reveal ให้ทุก section, ไม่เล่น animation วนโดยไม่มีผู้ใช้กระทำ,
  และไม่ขยับ layout ด้วย width, height, margin หรือ top/left
- ยึด opacity และ transform; หลีกเลี่ยง blur ใหญ่, parallax, canvas และ
  `will-change` ที่ค้างบนองค์ประกอบจำนวนมาก
- เมื่อ reduced motion เปิด ให้หยุดการเลื่อนภาพและคงภาพปกไว้ แต่ยังคง feedback
  ที่จำเป็นต่อการยืนยันว่าปุ่มหรือ state เปลี่ยนแล้ว

## วิธีทำงาน

1. ตรวจ branch, สถานะไฟล์, route, component, token และผลที่แสดงจริงก่อนเลือก scope
2. สรุปงานของผู้ใช้ จุดติดขัดที่เห็น และ motion thesis ก่อนแก้
3. แก้ flow ให้ครบทั้ง responsive layout, keyboard, focus, hover, active,
   loading, error, empty และ reduced-motion state โดยไม่ทำ controls เดิมหาย
4. สร้างหรืออัปเดต master prompt นี้เมื่อเพิ่มกฎถาวร แล้วใช้กฎเดียวกันกับโค้ด
5. build production; ตรวจหน้าที่แก้ด้วย browser ที่ desktop และจอมือถือเมื่อทำได้
   รวมถึงตรวจ console, overflow, contrast และ reduced-motion path
6. ไม่อ้างว่า push หรือ deploy แล้วจนกว่าจะตรวจ commit, deployment และ URL จริง
7. สรุปสิ่งที่เปลี่ยน เหตุผล ผลตรวจ และข้อจำกัดที่ยังเหลือเป็นภาษาไทย

## เกณฑ์รับงาน

- header ที่ความกว้าง 1,024–1,280 px ไม่ชนกัน และทุก route เดิมยังเข้าถึงได้
- มือถือมีเมนูที่อ่านง่าย ปิดได้หลังเลือกหน้า และไม่มี horizontal page overflow
- รูปตัวอย่างบนการ์ดทำงานด้วย pointer และ keyboard มีตัวนับ/เครดิต และหยุดตาม
  visibility กับ reduced-motion preferences
- Search suggestions เปิดด้วย focus, เลือกด้วย mouse/keyboard และมี transition สั้น
- การเคลื่อนไหวไม่ทำให้ข้อความหรือ controls กระพริบหาย, เลื่อน layout หรือบัง focus
- visual style ยังคง glass/clay ที่อ่านง่าย ไม่มี route หรือ state ที่ตกหล่น
- production build ผ่าน และเปิดดูผลจริงก่อนปิดงาน
